# Native macOS generation app on MediaGenerationKit

## Context
The Draw Things app's UI is cluttered, its history is hard to browse and reuse, managing models and LoRAs is painful, and there is no real queue. We want a native macOS SwiftUI app built on the same engine `draw-things-cli` uses: no RPC server, and previews, progress and cancel run in-process.

Pain points to fix first, in priority order:
1. Sensible per-model defaults, with advanced settings tucked away.
2. A browsable history with one-click reuse of settings.
3. Model and LoRA management.
4. A batch queue.

v1 covers text-to-image, LoRAs, image-to-image/references and video.

Working name: **Atelier**. It's a placeholder: the target and folder name are the only places it appears. Type names don't carry an app prefix (a convention carried over from draw-things-community's AGENTS.md).

## Foundation: MediaGenerationKit, not the CLI file
The CLI's generation code is almost all `private` inside `/Users/ianiv/Code/draw-things-community/Apps/DrawThingsCLI/DrawThingsCLI.swift`. `/Users/ianiv/Code/draw-things-community/Libraries/MediaGenerationKit` (SwiftPM product `_MediaGenerationKit`) is a clean public façade over the same `LocalImageGenerator`:
- **Generation:** `MediaGenerationPipeline.fromPretrained(_:backend:)` gives a pipeline with a mutable `configuration`. `generate(prompt:negativePrompt:inputs:stateHandler:)` reports `State` (downloading, encoding, `generating(step:totalSteps:)`, decoding…) plus lazily decoded `CGImage` previews (`MediaGenerationPipeline.swift:545-610, 886`). Cancelling the Swift `Task` cancels the generation.
- **Recommended settings:** `ConfigurationResolver.recommendedTemplate(for:loras:offline:)` already does LoRA-aware matching, which covers the "sensible defaults" goal.
- **Model catalog:** `MediaGenerationEnvironment.default` provides `downloadableModels`, `resolveModel`, `inspectModel` and `ensure(_:stateHandler:)` with download progress, and `maxTotalWeightsCacheSize` for keeping weights in memory.
- **LoRA import:** `LoRAImporter(file:version:).inspect()/import(to:)`. This is the flow we ran by hand with LoRAConverter.
- **Inputs for image-to-image and references:** `.file`/`.data` inputs and `.mask()/.moodboard()/.depth()`.

**Checked against the source at the pinned revision (Phase 1):**
- The module is `_MediaGenerationKit` (`import _MediaGenerationKit`), not `MediaGenerationKit` as AGENTS.md's sample shows.
- `DataModels` is `@_exported` (`MediaGenerationExecutionUtilities.swift:3`), so `SamplerType`, `SeedMode`, `GenerationConfiguration` etc. are usable without extra imports. `ModelZoo`/`LoRAZoo` are not exported.
- `ConfigurationResolver` is **internal**, not public. The app can't call `recommendedTemplate` or tell whether the catalog had an entry. What it gets instead: `fromPretrained` already merges the recommended template into `pipeline.configuration`. Atelier treats a configuration that still equals `GenerationConfiguration.default` (20 steps, UniPC AYS, guidance 4.5) as "not in the catalog" and applies its fallback table (`ModelDefaults.swift`).
- `MediaGenerationPipeline.Configuration` has no public init and isn't Codable; it can only be read off a pipeline and mutated. The sidecar dumps it field by field via `Mirror`. Phase 2's "Use settings" has to write fields back onto a fresh pipeline's configuration.
- `MediaGenerationEnvironment.default` is a `static var`; `externalUrls` is settable (nonmutating) and also sets `ModelZoo.externalUrls`. `.local(directory:)` builds a separate environment, so Atelier sets `default.externalUrls` and uses `.local`.
- `downloadableModels(includeDownloaded:offline:)` lists ModelZoo specs (built-in + custom.json), each with `isDownloaded`; "downloaded models" is that list filtered.
- `Result.write(to:type:)` writes encoded bytes directly; there is no metadata hook, so the PNG tEXt chunk needs re-encoding in the app (not done in Phase 1).
- **Live previews need app resources the community repo doesn't ship.** `Preview[i]` decodes with the tiny autoencoders (`canUseTAESD: true`), and `ImageConverter+CoreML.swift` force-unwraps `Bundle.main.url(forResource: "<model>_tae", withExtension: "zip")` (e.g. `flux_2_tae` for MOSS), so a missing archive traps at the first preview. A build phase in the Atelier target copies the 11 `*_tae.zip` from `/Applications/Draw Things.app` (override with `DRAWTHINGS_APP`); `GenerationEngine` only decodes previews when all are bundled, so a build without them still generates, just with no step previews.
- **Toolchain:** the macOS 27 SDK's `@State` macro plugin (`SwiftUIMacros`) ships only in Xcode, so builds need full Xcode. `Scripts/build.sh` sets `DEVELOPER_DIR` to `/Applications/Xcode.app` when `xcode-select` points at the Command Line Tools.
- `generate` returns `[Result]` and reports `State` with `generating(step:totalSteps:)` and a lazily decoded `Preview`; second-pass work (hires fix) shows as `.postprocessing`.

Each registers "<name> (8-bit)"/"(8-bit S)" with the same specification, and an interrupted copy resumes from the tensors already written. Debug builds compile the engine's C code without optimization, which makes quantizing far slower: use `Scripts/build.sh Release` for it. Converted Kromoss is published at huggingface.co/ianivs/Kromoss-DrawThings (Ianiv, 2026-10-23). - **Branching (decisions Ianiv, 2026-10-23).** Clicking an image (recent strip or History) makes it the current step; only the current step is recorded (in the project's key/value table as `image_seek_to`/`image_seek_to_lineage`, like Draw Things' seek; cleared after an append, so an open defaults to the newest step). The next run, Generate or Edit, appends after the current step (an Edit run after the canvas's step, its input): a plain append when that's the newest step (greatest lineage, then step number), otherwise a fork exactly as `pushHistory` with `canOverwrite` false. No branch names, no explicit branch command.
  - Fork from (L, t), M the greatest lineage: when t > 0 and L is below the greatest lineage at t (Draw Things' "sacred" step there; t is never past L's own last step, so `min(t, maxLogicalTime)` is t), every node, layer and moodboard row of L is renumbered, step numbers below t to M+2 and the rest to M+1, and the new step goes at (M+2, t+1); otherwise at (M+1, t+1). One transaction, reading the rows inside it.
  - Draw Things' parent rule (the step at t−1 with the greatest lineage not above one's own) stops holding after such a renumbering, so every step Atelier writes records its parent's image tensor in `profile_data` as `parent_tensor_id` (0 for none), next to `input_tensor_id`. The first fork or delete in a project first records it on every step lacking it, computed with the old rule while it still holds. `ProjectTree` reads the tree: the recorded parent when it names a step, else the rule. The main line is the newest step's ancestry; non-generated steps (Imported/Other inputs) collapse onto their nearest generated descendant (for the current step) or ancestor (for parent links) in the views.
  - Delete mirrors `deleteHistory`'s renumbering: later steps move down one step number on the deleted step's lineage and on higher lineages with no step at its number (below the greatest lineage there, when that's another step's). Its children record its parent as theirs. A deleted current step hands over to its parent, else the newest step.

**Phase 6 design: image to image (decisions Ianiv, 2026-10-22; review: Claude Doc "Image-to-image plan review").**
- **Engine facts (pinned revision).** MGK takes one image, one mask, any number of moodboard images and depth, all as encoded data (`MediaGenerationPipeline.executionInputs`). It aspect-fills and center-crops the image to the output size and knows no offset or zoom. Transparent pixels become the inpaint mask (`ImageConverter.tensor(from:)` reads alpha). With an image, strength 1 on a normal model takes the text-only path and ignores it; below 1 is img2img. Edit models (modifier `kontext`/`kontextKv`/`qwenimageEditPlus`/`qwenimageEdit2511`/`fl2va`/`ref2va`, which covers the FLUX.2 family and Klein) and Qwen Image 2.1 feed the canvas and every moodboard image in as references, even at strength 1. MOSS has no reference path. MGK sends every moodboard image at weight 1.0; for the reference models the engine only checks weight > 0, so weight is on/off there.
- **Generate / Edit toggle** in the composer. Generate never sends the canvas. Edit renders the canvas frame (the configured size, the image placed by the canvas zoom and offset, transparent where the image doesn't cover) to a PNG and passes it as the image input, so placement and outpainting come from the canvas. Bringing an image in (drop, paste, Open Image… ⌘O) switches to Edit. After an Edit run the result is on the canvas and the mode stays Edit, so refining is one click.
- **Moodboard**: a column on the right edge of the canvas (glass panel over the canvas), shown for models that take references. Images come from drops (files, the recent strip, History), its + button, and "Add to Moodboard" on the canvas and recent strip. Each image has a weight (0 to 100%, slider in a popover); weight 0 leaves it out, as the engine does. Sent in both Generate and Edit. Kept across launches in `~/Library/Application Support/Atelier/Moodboard/`.
- **Projects, as Draw Things stores them**: an image brought in from outside is written as an Imported step (`generated` false, reason imported, so History doesn't list it) before the step generated from it. Every step generated with a moodboard writes its images as `shuffle_<id>` tensors (id band 1.6B–1.8B), `tensormoodboarddata` rows (index, shuffle id, weight) and `shuffle_data_stored`; the preview id adds shuffle id × round(weight × 1000) per image, like `pushHistory`. Use Settings restores the moodboard. Delete removes the rows and tensors.
- **Input link (Use Settings on Edit steps).** In Draw Things every step's input is the canvas, i.e. the step before it; it has no field saying a step used the canvas (`reason` is Generate either way), and Atelier's Generate mode ignores the canvas. So: an Edit run whose canvas isn't exactly a step's image (an image from outside, moved or zoomed, another size) first appends the rendered canvas as a non-generated step (reason Imported for an image from outside, Other otherwise), so the generated step's parent is always its input. The generated step records the input's tensor id in `profile_data`: Draw Things' `GenerationProfile` JSON (`timings`, `duration`) plus `input_tensor_id`, which Draw Things' Codable decoding skips. The node's own `tensor_id`/`mask_id` were not used: Draw Things loads those into the canvas and counts them as references when deleting. Use Settings on a step with `input_tensor_id` puts the parent step's image on the canvas, fitted, in Edit mode, so rerunning reproduces it; when the parent's image isn't that tensor (the input was deleted and steps renumbered), it shows the result and a status-bar note. History still lists only generated steps. Checks: `--project-check` (format) and `--edit-input-check` (real runs).
- **Engine cache bug (Flux.3), worked around in the app.** Flux.3 builds its reference layers (embedder, refiner block, modulations) only when a run has references, but the weights cache keeps the model's weights under the model file either way. A run with references after one without finds the cache, skips the file and leaves those layers unloaded: the canvas is ignored or the result is a patchwork of tiles. The model preloader also reuses a kept model without comparing the inputs it was compiled for (`ModelPreloader.retrieveUNet`). FLUX.2 Klein isn't affected. `GenerationEngine` remembers the last run's model and image inputs (canvas on/off, image sizes); when they change on the same model it sets `total_weights_cache` and `keep_model_in_memory` to 0 and back in the engine workspace, emptying both caches so that run loads from disk.
- **Not in this phase:** mask brush (masks only come from transparency), depth, ControlNets, per-image weights beyond on/off for reference models (would need calling the engine past MGK).

**Phase 7 notes (queue, decisions Ianiv 2026-10-23):**
- Generate always queues. Idle, the job runs at once; during a run it waits. Each job snapshots prompt, settings, seed, canvas render (Edit) and moodboard when queued. An Edit job queued during a run uses the canvas as it was before that run's previews covered it (`canvasBeforePreview`).
- ×N under Generate (`CreateModel.count`, not saved): Random on rolls a seed per image; Random off counts up from the Seed field (`seed &+ i`). The Seed field and Random are untouched. No prompt variations (Ianiv).
- Lineage: jobs queued while the current step is the one the queue left (`expectedCurrent`) share a line; each job takes the line's latest result as parent when it starts, so reordering and cancelling still give one line. Picking another step before queuing starts a new line. Edit jobs follow their input as before. Repeated Edit jobs from an imported/moved canvas reuse the input step the first one saved (`canvasKey`).
- Stop cancels only the running job; the queue moves on. Pause (Queue toolbar only, Ianiv) holds the waiting jobs once the running one finishes or is stopped.
- Agents' `generate` calls are queue jobs (shown with a network icon); cancelling the MCP call removes or stops the job.
- Waiting and running jobs (not agents') are written at quit to `~/Library/Application Support/Atelier/Queue/` (index.json, PNGs) and restored paused; settings go back on the model's defaults (`savedRequests`). Not for scripted runs.
- `CreateModel.isLoadingModel` is now separate from the run phase, so switching models while a job runs doesn't touch its progress. `isBusy` is still "running or loading" for Automation.

## App architecture (`~/Code/Atelier/Sources/Atelier/`, macOS 27)
- **`GenerationEngine`** (actor). Owns a cached `MediaGenerationPipeline` per model and recreates it only when the model changes. Runs one job at a time and publishes progress and the preview `CGImage` to the UI on the main actor.
- **`JobQueue`** (`@Observable`, `Sources/Atelier/Queue/`). Waiting jobs, the running one and recent ones; each job is a `GenerationEngine.Request` snapshot. Supports pause, reorder, cancel and retry. See Phase 7 notes.
- **`HistoryStore`**. Since Phase 5, history lives in **projects** in Draw Things' file format (one `.sqlite3` per project under `~/Pictures/Atelier/Projects/`), see Phase 5 notes. Before that it was one folder per day under `~/Pictures/Atelier/` with a PNG plus `.json` sidecar per output; those are imported once into the "Atelier" project and left in place.
- **`ModelLibrary`**. Wraps the `MediaGenerationEnvironment` catalog and LoRAZoo. Shows downloaded vs available, download progress and disk usage, and filters LoRAs by the selected model's version.

**UI layout:** a `NavigationSplitView` with sidebar sections Create, Queue, History, Models and LoRAs.
- **Create:** canvas (live preview, then the result), a prompt composer under it, and a settings inspector. Phases 1 and 2 shipped a simple version with prompt, model, size and seed in an Essentials section and a collapsed Advanced section. Phase 3 replaces it with the design below.
- **History:** a grid with a detail pane. Actions: "Use settings" (loads them into Create), "Rerun with new seed", "Reveal in Finder", delete, and filter by model or prompt text.
- **Models / LoRAs:** a catalog list with search, download, delete and drag-to-import (`.safetensors` goes through LoRAImporter or ModelImporter).

**Settings inspector (Phase 3).** Full write-up with rationale: `/mnt/project-files/design/settings-inspector.md` (project files).
- **Decisions (Ianiv, 2026-10-21):** the prompt is not in the inspector; layouts are switched by hand, not per model family; presets are wanted, separate from layouts.
- **Layout of Create.** The prompt composer sits under the canvas: multi-line, grows to about 6 lines, negative prompt as a disclosure, Generate beside it. The toolbar holds the model picker, preset menu, Generate/Cancel and the inspector toggle, and is customizable (`.toolbar(id:)`). The inspector holds a search field, a **Changed** group when anything differs from defaults, the current layout's sections, and "Reset All to Model Defaults" at the bottom.
- **macOS conventions.** Inspector collapsible and remembered (`@SceneStorage`, `InspectorCommands`, ⌥⌘I). Dense label/control rows with `.help` tooltips instead of captions. Feature sections (hires fix, tiling, refiner, TeaCache, CFG-Zero*, upscaler) get an enable checkbox, reset and disclosure in the header, with expansion persisted. Changed values are marked, with per-row reset. Every row has a context menu: Reset to Default, Copy Value, Hide from/Show in Inspector. Sliders pair with editable number fields. Size is one row that opens a popover (aspect grid, megapixels, W/H); LoRAs and sampler use searchable popovers or menus with readable names. Setting changes are undoable, with slider drags coalesced. The inspector stays editable while a job runs; edits apply to the next run. Shortcuts: ⌘L focus prompt, ⌘R roll seed.
- **Settings registry.** One descriptor per `Configuration` field (about 80): stable id, title, help, section, control kind and range, key path, parent toggle, and an applicability predicate on the selected model (`MediaGenerationResolvedModel.version`, video or not). The inspector, search, changed markers, reset, presets and History's "Use settings" all read from it. This also lets "Use settings" write back every field, not just the Phase 2 subset.
- **Visibility.** Each setting is **shown**, **tucked** (under a "More: N" disclosure in its section) or **not applicable** (hidden automatically for the selected model). Everything stays reachable through the search field, a Show All toggle (or ⌥), and the Changed group, which always surfaces tucked settings whose value differs from the model default.
- **Layouts** (which controls are shown, their order, which sections start expanded). Edit with right-click Hide/Show or a Customize Inspector… sheet (grouped checklist, drag to reorder). Stored as JSON in `~/Library/Application Support/Atelier/Layouts/`, exportable and importable. Built-ins: Simple, Standard, Everything. Switched by hand from the inspector header menu.
- **Presets** (saved values). Toolbar menu with "Save Current Settings as Preset…"; a preset applies on top of the model's defaults. Stored as JSON next to layouts and exportable. Presets don't change the layout, and layouts don't change values.

**Settings:** models directory (saved in UserDefaults; unset, it follows MGK: `DRAWTHINGS_MODELS_DIR`, else `~/Documents/Models`; no machine-specific path in code, Ianiv 2026-10-22) and weights cache size.

## Repo, build and packaging
- Git repo at `~/Code/Atelier` with a checked-in `Atelier.xcodeproj` (macOS 27 deployment target, so Liquid Glass APIs need no availability checks): an app target `Atelier` (`Sources/Atelier/`) and a static framework `ProjectFormat` (`Sources/ProjectFormat/`, its own module because its enum names clash with DataModels').
- Package dependencies are Xcode package references pinned to revisions (Project > Package Dependencies): draw-things-community `8dbbb5c69b83c6312eb10622611d46a943de6f88` (upstream `main` as of 2026-10-21, includes MOSS Image support), and dflat and flatbuffers at the revisions the engine pins. Bump the engine revision deliberately to pick up new models.
- The only library product upstream exports is `_MediaGenerationKit`, so the app uses **only MGK's public API**. Fill the gaps above in the app (fallback defaults, LoRA registration via `custom_lora.json`, video writing, metadata).
- If the app truly needs an engine change or a non-exported module (e.g. `ModelZoo`/`LoRAZoo`), switch the dependency to the local fork (drag `../draw-things-community` into the project as a local package, which overrides the remote one), make the change there as a separate commit, and note it here.
- **Known fork-only fix:** `327c0386` "Fix Qwen3 attention layout when vision embeddings are injected" (`Libraries/SwiftDiffusion/Sources/Models/Qwen3.swift`) isn't upstream. In phase 6 (image-to-image/references), test reference-image generation on models whose Qwen3 text encoder takes vision embeddings. If it's broken, point the dependency at the fork.
- `Scripts/build.sh [Debug|Release]` runs `xcodebuild` on the project (derived data and package checkouts under `build/`) and copies the result to `build/Atelier.app` for scripted runs. Signed automatically with the personal team, bundle id `ca.blogaholics.Atelier`.
- No SwiftPM package of our own (removed 2026-10-22, Ianiv): an SwiftPM executable is stamped `sdk 14.0` when Xcode builds it, which breaks i8x models. Check a build with `vtool -show-build`.
- Keep generated build products and `build/` out of git via `.gitignore`.

## Phases (each one usable on its own)
1. Skeleton: model picker, prompt, Essentials, generate with live preview and cancel, save to history folder.
2. History browser with "Use settings" and rerun.
3. Settings inspector: prompt composer under the canvas, inspector conventions, settings registry covering the full `Configuration`, search and Changed group, customizable layouts, presets. Comes before the queue because the queue needs an inspector that stays editable while jobs run.
4. Model and LoRA library: download, import, delete, filtered LoRA picker. Moved ahead of the queue (Ianiv, 2026-10-21).
5. Projects in Draw Things' file format, replacing the PNG history (Ianiv, 2026-10-22). Atelier creates and keeps its own projects; they aren't shared with Draw Things.
6. Image-to-image and reference inputs (moved ahead of the queue, Ianiv 2026-10-22). See Phase 6 design.
7. Queue and batch count (prompt variations dropped, Ianiv 2026-10-23). See Phase 7 notes.
8. Video: frames, output writing and an inline player.

**Performance settings (Settings ⌘,):**
- Mirrors Draw Things' Machine Settings: JIT Weights Loading, Weights Cache Size, Metal Flash Attention, Apple Neural Engine for 8-bit S models, Merge LoRA, High Resolution Preview. Stored in UserDefaults as `performance.<key>`; Automatic (-1 or unset) leaves the engine's own default (`ModelPreloader.update…(nil)`, `DeviceCapability`).
- The engine reads these from its workspace dictionary under DT's keys (`external_store_v2`, `total_weights_cache` in 8 GiB units, `use_mfa_v4`, `use_mfa_apple_neural_engine_v2`, `merge_lora`). MGK keeps the workspace internal, so `GenerationEngine` finds it by reflection and writes the keys before each run; Dflat calls the preloader's subscribers synchronously, so a change lands on the generation queue ahead of that run.
- MGK only builds its engine on the first generation, and the preloader reads the keys as it subscribes. `GenerationEngine` first runs a generation that fails before loading anything (a moodboard image that doesn't decode) so the first real run gets the settings too.
- High Resolution Preview off decodes previews straight from the latent (`ImageConverter.cgImages(canUseTAESD: false)`) and scales them to the output size; this also gives previews when the `*_tae.zip` archives aren't bundled.
